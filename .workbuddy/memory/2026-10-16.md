# 2026-10-16 第九轮续：NCM 桥诊断增强（屏幕/诊断报告可见卡点）+ 排查纠偏

## 纠正两个早前假设
- `control=3/-1 data=4/-1` 里的 **-1 是 API 17 预期值**：`UsbInterface.getAlternateSetting()` 是 API 21+，`UsbDescriptorCompat.alternateSetting` 在 API 17 一律返回 `ALTERNATE_SETTING_UNKNOWN=-1`（`UsbDescriptorCompat.kt:150`）。**非 bug**，NCM 功能发现正常。
- 截图最后可见行停在 `ncm config=`（openNcm 起点）→ 卡点在 `NcmUsbBridge.open` 内部或其后，属 **USB 层以下**（claim/setInterface/controlTransfer），**不是 iPhone「信任此电脑」**（Trust 只在 USB 之上的 Lockdown 层，runStack 到 Pairing 阶段才有，且那会先打出 `wired USBMUX host opened` 等行）。故本轮假设的 Trust 成因大概率不成立。

## 改动（纯诊断增强，行为零变化）
- `shared/.../transport/NcmUsbBridge.kt` `open()`：把内部 4 处 `Log.i`（`ncm descriptor hostMac=` / `claim iface=` / `setInterface iface=` / `ncm status endpoint=`）改为走 `onDiagnostic`，并新增 `ncm open: reading host MAC` / `claiming control iface` / `claiming data iface` / `setInterface data iface` / `returning bridge` 入口/出口诊断——**屏幕诊断(usbDiagView, 仅最后12行) + 诊断报告(diplay.log) 均可见**。
- `shared/.../orchestration/CarPlayController.kt` `openNcm`：`openDevice` 之后新增 `connectionDiagnostic("ncm openDevice ok; entering NcmUsbBridge.open ...")`，覆盖「openDevice 本身阻塞」盲区。
- `IphoneCarPlayConfiguration.TAG` 仍被 `send`/`drainStatus` 使用，无未用 import；`Log` 仍被多处使用。

## 判据（用户侧载后看屏幕末几行 + 诊断报告）
- 仅见 `ncm config=` 后无新行 → `openDevice` 阻塞（内核未放行第二个连接）。

# 2026-10-16 无蓝牙引导真机验证：EXISTING_WIFI 模式在 API 17 被拒 → loadWirelessHotspotMode 自愈修复

## 报错（真机 0.2.19-api17，无蓝牙引导开关已生效）
- 日志：`wireless bring-up generation=1 starting` → `wireless bring-up failed: WirelessStartupException: Existing Wi-Fi mode requires Android 5.0 or newer. Pick the car hotspot mode instead. @ CarPlayController.startWirelessHotspot(CarPlayController.kt:2555)`
- 好消息：`wireless bring-up` 起点已到达 → 无蓝牙引导开关 + 入口放宽**已生效**（不再弹蓝牙配对框），卡在热点模式选择。

## 根因
- 设备存储的无线模式 = `EXISTING_WIFI`（来源：旧设置/备份恢复，UI 在 API 17 不呈现该选项）。
- `ExistingWifiManager` 依赖 `ConnectivityManager.NetworkCallback`（API 21），API 17 上类加载即 NoClassDefFoundError → `CarPlayController.kt:2562-2569` 守卫拒绝（正确行为，已有测试 `existingWifiIsRejectedOnApi17InsteadOfCrashing`）。
- 缺口在 `AirPlayPersistence.loadWirelessHotspotMode`（:366-374）：只把 `LOCAL_ONLY_HOTSPOT` 回落 MANUAL，**未对 API<21 的 EXISTING_WIFI 自愈** → UI 不显示选中态、用户看不到当前模式，连接才报错。

## 修复（2 文件）
| 位置 | 改动 |
|---|---|
| `AirPlayPersistence.kt` `loadWirelessHotspotMode` | `when(mode)` 增加 `EXISTING_WIFI && SDK_INT < LOLLIPOP → MANUAL`（与 LOCAL_ONLY_HOTSPOT 同款自愈 + 写回），Build 已 import |
