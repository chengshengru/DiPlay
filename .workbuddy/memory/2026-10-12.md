# 2026-10-12 有线 CarPlay：0x52 IN 生效（iPhone 弹"信任此电脑"），新卡点 = claim USBMUX

## 重大进展
- 0x52 回退为 IN(0xc0) 生效：真机第二轮授权后 **iPhone 弹出"要信任此电脑吗？"窗口**（此前从未出现）。
- 链路已走到：`permission granted` → `USB configuration ready=...`（**find() 成功，CarPlay 配置已暴露**）→ `opening iPhone USB data paths` → `stage=SelectingConfiguration` → `stage=OpeningDataPaths` → `stage=Failed`。
- **新错误**：`ERROR Android could not claim USBMUX interface 1` —— `IphoneUsbHost.openIap2UsbSession` 里 `connection.claimInterface(usbMux, true)` 返回 false。

## 分支/代码现状（重要）
- 已从 `port/wave8-increment` 切到 **`port/wave9-increment`**（HEAD `80d28cb6`「迁移0.2.18」），工作树干净（前几轮改动已随 wave 提交）。
- wave9 引入 `shared/.../transport/UsbConfigurationSelection.kt`（移植 main #618/#518）：`IphoneUsbHost.selectConfiguration` 现在先 `UsbConfigurationSelection.select`——首次 SET_CONFIGURATION 失败时，逐接口 `claimInterface(true)`+`releaseInterface` 强制分离内核驱动，再重试 SET_CONFIGURATION；并用标准 GET_CONFIGURATION 读回活动配置。
- **上游对比**（WebFetch `shilapi/xcertplay` master `IphoneUsbHost.kt`）：上游用 API21+ 的 **`connection.setConfiguration(configuration)` 框架 API**（走内核 `USBDEVFS_SETCONFIGURATION` ioctl，**会更新内核 actconfig**）；本 fork（API17）没有该方法，只能发**原始 SET_CONFIGURATION 控制传输**——Linux 内核**不会**因用户态原始控制传输刷新 `dev->actconfig`，于是随后 `USBDEVFS_CLAIMINTERFACE` 去 claim 只存在于 config 6 的接口就失败（ENODEV/EBUSY）。这是当前 claim 失败最可能的根因。
- 另：USBMUX 的 claim 此前只有 1 次、无重试；NCM 路径早已用 `NcmUsbBridge.retryUsbSetup`（5次/100ms）兜底 #518 的"内核驱动 detach 与 claim 之间重新绑定"。

## 本轮改动（`IphoneUsbHost.kt`，框架层，未碰爬虫）
1. USBMUX claim 改为 `claimWithRetry(connection, usbMux)`（5 次 /100ms，对齐 `retryUsbSetup`）。
2. 新增 claim 失败前一行的 `onDiagnostic(...)`（→ 屏幕诊断覆盖层，无需 logcat）：
   `usbmux pre-claim config=<label> id=<> index=<> active=<GET_CONFIGURATION 设备视角> rawConfigs=[描述符里所有配置值] iface=<> alt=<> class=a.b.c endpoints=<n> out=<> in=<> deviceIfaces=[设备全部接口 id/alt:class.subclass.protoxN]`。
3. claim 失败信息补齐 `active=... deviceIfaces=[...]`；成功则打 `usbmux claimed iface=<> attempts=<>`。
4. 新增私有辅助 `claimWithRetry` / `describeDeviceInterfaces`，常量 `USB_CLAIM_ATTEMPTS=5`、`USB_CLAIM_RETRY_MILLIS=100L`。
- 注：wave9 已无 `USB_VENDOR_DEVICE_OUT`/`CARPLAY_CONFIGURATION_ENABLE` 死常量；companion 新增 `USB_STANDARD_DEVICE_IN=0x80`、`GET_CONFIGURATION_REQUEST=0x08`（供 activeConfiguration）。

## 验证
- `./gradlew :shared:compileDebugKotlin :common:compileDebugKotlin :mobile:assembleDebug` → **BUILD SUCCESSFUL**（5m24s，仅既有 CarPlayHostActivity/DiPlayActivity deprecation 警告，零新增）。
- APK：`mobile/build/outputs/apk/debug/mobile-debug.apk`（21M，sha1 `d370d43b99b77b75add7e45ace1e81e0bacad4ef`）。未提交。

## 待真机复验（侧载后看屏幕诊断行 `usbmux pre-claim ...`）
- **`active=6` 但 claim 仍失败** → 确认"设备已切到 config 6、内核 actconfig 陈旧"：API17 无法用框架 `setConfiguration`，下一步备选
  (a) 只发一次 SET_CONFIGURATION 后**不依赖内核**、改用"重新枚举让内核重读"（0x52 后再等一次 ATTACH 重开连接）；
  (b) 通过反射/JNI 触达 `USBDEVFS_SETCONFIGURATION`(重)；
  (c) 若 iPhone 重枚举后默认 active 已是 config 6，则**完全跳过 SET_CONFIGURATION**直接 claim。
- **`active≠6`** → SET_CONFIGURATION 未生效或 target 值算错（看 `rawConfigs` 与 `index` 是否对得上），需修配置值映射。
- **`active=6` 且 claim 成功（attempts>1）** → 就是 #518 驱动重绑竞争，重试已解决，进入 iAP2/NCM 阶段。

# 2026-10-12 太阳图标中心黑点修复（矢量透明 fill + minSdk 差异）

## 现象
- 设置界面外观切换按钮：当前分支太阳（ic_dp_day）中心有黑点，main 分支干净。深色/亮色模式均如此。

## 根因
- 图标 XML（`ic_dp_day.xml` / `ic_dp_chevron.xml` / 11 个 `ic_maneuver_*`）均为**纯描边**矢量，但 path 带 `fillColor="@android:color/transparent"` 或 `fillColor="#00000000"`（透明填充）。
- 关键差异在 `minSdk`：**main `minSdk=25`** → VectorDrawable 由框架运行时直接渲染（API≥21 原生支持），透明 fill 被正确忽略 → 仅白色描边轮廓，无黑点。
- **当前分支 `minSdk=17`** → 因 <21，AGP 在构建期为低版本生成 **PNG 兜底**；旧 AAPT 矢量转 PNG 栅格化器把透明 fill（0x00000000）渲染成**黑色实心** → C140A(API17) 上太阳/箭头中心变成黑色圆盘。
- 注：`UiCompat.setImageTint(ACCENT)` 在 API17 是 no-op，染色不是设备黑点成因；main 参考截图取自 API21+，故不一致。

## 修复（资源层，零代码改动，未碰爬虫）
- 从全部「纯描边 + 透明 fill」矢量路径中**移除 `fillColor` 属性**：透明=无填充，移除后 main(API25) 渲染完全一致（透明本即无填充），C140A(API17 PNG) 不再生成黑盘。
- 受影响 13 文件：`ic_dp_day.xml`、`ic_dp_chevron.xml`、以及 `ic_maneuver_{destination,left,right,roundabout,sharp_left,sharp_right,slight_left,slight_right,straight,u_turn_left,u_turn_right}.xml`。
- `ic_dp_chevron` 与 ic_dp_day 用 `Edit` 移除独立成行的 `@android:color/transparent`；11 个 maneuver 用脚本按行内 `fillColor="#00000000"` 精确移除。Grep 复核无残留。
- `ic_dp_night.xml`（月亮，fillColor=#FFFFFFFF 实心白）不受影响，未改。

## 验证
- 13 文件 XML 良构校验（minidom parse）全部通过。
- `./gradlew :common:mergeDebugResources --offline` → 无报错（AAPT 已接受并栅格化矢量）。
- 真机侧载后目测太阳/箭头中心应为空心（无黑点）。
- 备选更彻底方案（未采用）：`common/build.gradle.kts` 加 `vectorDrawables { useSupportLibrary = true }` + 全量改用 `AppCompatImageButton`/`AppCompatResources` 运行时加载矢量，可一次性根治所有低版本矢量渲染问题，但涉及大量程序化 ImageView 改造、侵入性高，本次仅做最小资源修复。
