# 2026-10-17 无蓝牙引导真机第2关：MANUAL 热点采样恒被拒（getActiveNetwork 是 API 23+）

## 真机现象（0.2.19-api17 截图）
- 已越过上一关：`wireless bring-up generation=1 starting`、`mfi/ready`、`STEP wifi/ap: starting the wireless CarPlay access point`。
- 卡点：`generation=1 hotspot sample rejected: network_changed=true apEnabled=true`，UI 提示「请确认车机热点已开启，且名称和密码与 DiPlay 设置一致」。
- 同屏 `legacy hotspot ownership=observed tethered=[wlan0] wifiRegexes=[wlan0, wlan1]` → 原厂反射可读、热点确已开、AP 接口就是 wlan0。

## 根因
- `ManualHotspotInterfaces.sample()` 用 `connectivity.activeNetwork` 前后两读做「采样中途网络未变」的一致性判据，但 **`getActiveNetwork()` 是 API 23+**（仓内 `NetworkCompat.isConnected` 以 `ApiLevel.M` 守卫同款调用）。
- API 17 上调用抛 `NoSuchMethodError` → 被 `runCatching` 吞 → `before.isSuccess=false` → `consistent` **恒为 false** → `selectHotspotInterface` 每次都打 `network_changed=true` 并拒绝 → `ManualHotspotReadiness.await` 等到超时 → `HOTSPOT_NOT_READY`。
- 即「观测不到」被误判成「网络变了」。

## 修复（2 处 + 1 测试文件）
| 位置 | 改动 |
|---|---|
| `shared/.../network/ManualHotspotInterfaces.kt` | 新增 `internal fun activeNetworkComparable(sdkInt) = sdkInt >= M` + `activeNetworkSample(): Result<Network?>`（API<23 直接 `Result.success(null)`，不观测即不否决）；`sample()` 的 before/after 改调它。API≥23 行为不变 |
| `shared/.../network/ManualHotspotManager.kt` | `frequencyFromConnectionInfo()`：`WifiInfo.getFrequency()` 同为 API 21+，API 17 抛 `NoSuchMethodError`（Error 类，绕过控制器 `catch(Exception)`）→ 加 `SDK_INT < LOLLIPOP return null`（信道另走 scanResults/apConfiguration） |
| `shared/src/test/.../ManualHotspotInterfacesTest.kt`（新） | sdk=17 一致性为 true（**修复前实测失败，复现成功**）；sdk=17 upstream/defaultInterface 为 null；纯函数边界 17/22→false、23/36→true |

## 关键坑（测试口径）
