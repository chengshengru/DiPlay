# 2026-10-15 有线 CarPlay 第八轮：ioctl 常量错写 RESETEP 根因定案 + 跨 API 影响评估

## 复盘：上一轮「内核切配置」为何仍失败（决定性根因）
- 第七轮侧载后用户反馈「还是一样的错误」：`claimProbe=[0=ok,1..5=fail]` / `could not claim any USBMUX interface`。
- 逐行比对 NDK 21.1.6352462 内核头 `sysroot/usr/include/linux/usbdevice_fs.h`：
  - `:129 #define USBDEVFS_RESETEP _IOR('U', 3, unsigned int)`
  - `:131 #define USBDEVFS_SETCONFIGURATION _IOR('U', 5, unsigned int)`
  - `:150 #define USBDEVFS_DISCONNECT _IO('U', 22)`
- **上一轮 `usb_config_jni.c` 把 `USBDEVFS_SETCONFIGURATION` 手写成 `_IOR('U', 3, ...)` —— 实际是 `USBDEVFS_RESETEP`（复位端点），且源文件未 include `<linux/usbdevice_fs.h>`，导致 `#ifndef` 兜底错常量生效。**
- 后果：内核 ioctl 发出的是 **nr=3(RESETEP)**，配置**从未被真正切过去**；`result=0` 只是 RESETEP 复位成功的假象 → 日志伪报 success → 但内核 `actconfig` 没变 → `claimProbe` 仍是 `[0=ok]`。这就是「还是一样的错误」的真正原因。

## 修复（仅框架层，未碰爬虫/KSPlayer）
1. `shared/src/main/jni/usb_config_jni.c`：新增 `#include <linux/usbdevice_fs.h>`（让常量永不失真），并把错写的 `_IOR('U', 3, ...)` 改回 `_IOR('U', 5, ...)`；注释标注「hand-copy ioctl 编号是首版踩坑」。
2. `shared/.../transport/UsbConfigurationKernel.kt`：`LIBRARY_UNAVAILABLE` 由 `-1` 改 `-1000`（区别于任意负 errno）；新增 `val available: Boolean get() = loaded`。
3. `shared/.../transport/IphoneUsbHost.kt`：新增 `@Volatile var lastConfigurationSwitch: String?`；`selectConfiguration`/`switchConfiguration` 三处把诊断串写入该字段；库未加载显式 `onDiagnostic("usb config kernel library unavailable; kernel path skipped")`；claim 失败异常信息追加 `switch=[...]`（对抗屏幕日志滚动窗口丢失）。

## 字节/反汇编验证（修复入包判据）
- 宏展开：`old 0x80045503`(RESETEP) vs `new 0x80045505`(SETCONFIGURATION)，差 0x2；`DISCONNECT _IO('U',22)=0x00005516`。
- arm64 反汇编：`mov w1, #21765`(0x5505) + `movk w1, #32772`(0x8004) = `0x80045505`；armeabi-v7a `movw r1,#21765`/`movt r1,#32772`；旧 `21763`(0x5503) 计数 0 —— 证明修正已编入 4 ABI。
- 注：arm64 立即数按指令位打包，查 `.so` 裸小端半字 `0x5505` 字节会出现 0 次（误判）。须用 `llvm-objdump` 反汇编确认。

## 构建与交付
- `:shared:testDebugUnitTest --tests UsbConfigurationSwitchTest --tests UsbSetupDiagnosticsTest :mobile:assembleDebug` → **BUILD SUCCESSFUL in 33s**（JAVA_HOME=`/usr/libexec/java_home -v 17` → corretto-17.0.20.1；旧 `Apps/AmazonCorretto/...` 路径无效）。
- APK：`mobile/build/outputs/apk/debug/mobile-debug.apk`（25,730,091 字节，sha1 `370e79b7f9a12311429b14d807de958838727a95`，构建于 2026-10-15 07:27）；`libxcertplay_usbconfig.so` 已打入 4 ABI。

## 跨 API 版本影响评估（用户问「此次改动会影响其他版本api吗」）
- **结论：仅影响 API 17–20 路径，对 API 21+ 零影响。**
- 调用链：`IphoneUsbHost.selectConfiguration` → `switchConfiguration` → `UsbConfigurationSwitch`（内核 ioctl 优先）→ 仅在 `UsbDescriptorCompat` 的 **API 17–20 分支**（原始 SET_CONFIGURATION 控制传输兜底失效处）被启用。
- API 21+ 走框架 `connection.setConfiguration(UsbConfiguration)`（系统服务直接切内核 `actconfig`），**完全不进入 JNI / ioctl 路径**，故本次 JNI 常量修正只在 API 17–20 真机上生效。
- JNI 本身（raw `USBDEVFS_*` ioctl）是 Linux 内核接口，与 Android API level 无关；但因调用点被 `SDK_INT <= KITKAT` 门控，**不会改变 API 21+ 行为，也不会在高版本上被加载执行**。
- `LIBRARY_UNAVAILABLE=-1000` 与 `available` 属纯逻辑常量，不影响任何已有功能分支语义。

## 复验判定（请用户侧载后看屏幕末两行）
- 预期：`usb config kernel SET_CONFIGURATION(6) fd=… result=0 … ok=true` → 随后 `claimProbe` 多号 =ok → `usbmux claimed iface=…` → 进 iAP2/NCM → iPhone 弹 CarPlay 信任窗口。
- `result=-16`(EBUSY) → 仍有接口绑驱动，需更强 detach（USBDEVFS_DISCONNECT 被拒时走 per-interface 强制 claim）。
- `result=-5`(EIO)/`-19`(ENODEV) → 内核拒绝切配置，查是否有其他 usbfs 持有者。
- `switch=[usb config kernel library unavailable; kernel path skipped]` → JNI 库未加载，需确认 4 ABI `.so` 随包打入。

## 待办
- 真机复验（用户侧）：确认 `claimProbe` 多号变 ok、iPhone 弹信任窗口。
- 工作区仍未提交（本轮 JNI/kt 改动 + 波次十二 55 改/21 untracked）；提交需构建三关先绿。
