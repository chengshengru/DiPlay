## 本轮崩溃：ClusterMapPresentation.findDisplay
- 现象（API17 车机/模拟器）：首页→设置→"仪表集群地图"类目崩
  `NoSuchMethodError: android.content.Context.getSystemService`
  @ `ClusterMapPresentation$Companion.findDisplay(ClusterMapPresentation.kt:196)`
  ← `DiPlayActivity.allSettingsSections$12.invoke(DiPlayActivity.kt:1466)`
  ← `renderSections(1203)` ← `advancedSettings(1178)` ← `settingsCategoryContent(807)` ← `render(498)`。
- 根因（同一族）：`Context.getSystemService(Class)` 是 **API 23** 才有的重载；API17 只有
  `getSystemService(String)`。dalvik 只把缺方法指令替换为 throw 桩 → 执行即 `NoSuchMethodError`
  （`NoSuchMethodError` 是 `Error`，不被 `catch (RuntimeException)` 接住）。日志中
  `VFY: unable to resolve virtual method 138: ...getSystemService(Ljava/lang/Class;)` + `replacing opcode 0x6e` 即铁证。
- 修复模式（全仓库统一）：`context.getSystemService(Context.X_SERVICE) as? X`。
  行为在 API≥23 上**完全等价**（Class 重载内部就是按 class→name 再走 String 重载）。
  注意 `Context.*_SERVICE` 是 `static final String` 常量，编译期内联 → 即使该常量 API 级别更高也无运行时引用风险。

## 语义决策（可空性）
- 原代码用 `?.`/`?: throw`/`?.let` 的 → `as?`（可空）；
- 原代码当非空用的（`CarPlayBonjour.multicastLock`、`AndroidCarPlayLocationProvider.locationManager`）
  → `requireNotNull(x as? T) { "… is unavailable" }`，**保持字段类型非空**，不改调用点，且报错信息比原 NPE 清晰。
